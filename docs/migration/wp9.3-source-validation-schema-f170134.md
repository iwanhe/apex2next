## 4. Tables and constraints

All six `GENERATED BY DEFAULT ON NULL AS IDENTITY` columns are now `bigint GENERATED BY DEFAULT AS IDENTITY`. The virtual column `REQUEST_LINES.LINE_AMOUNT` is now `numeric GENERATED ALWAYS AS (qty * unit_price) STORED`. All 8 CHECK predicates are emitted unchanged. The three post-create FKs are emitted as `ALTER TABLE` statements after all tables exist. The `ON DELETE CASCADE` on request lines is preserved. FK child columns declared as unconstrained `NUMBER` (`requests.department_id`, `request_lines.request_id/item_id`) are aligned to the referenced `bigint` keys. Without that alignment PostgreSQL would reject the FK (numeric vs bigint).

Verified on PostgreSQL 16 (`tests/test_wp93_postgres.py`):
- the catalog (columns, types, nullability, identity, generated, constraints, indexes, views) equals `expectedCatalog`;
- identity values are generated; explicit IDs plus the post-load script continue the sequence correctly;
- `line_amount` is computed, and an explicit value is rejected;
- every CHECK rejects an invalid value; UNIQUE and FK violations are rejected; cascade delete removes lines;
- defaults: `status = 'DRAFT'`, `request_date = CURRENT_DATE` at midnight, `active_yn = 'Y'`;
- re-applying the migration fails with no partial change, and a fresh apply produces an identical catalog.

## 6. Findings that need a decision (owner sign-off)

1. **SRC-001: page 100 KPI region does not match the view in `install.sql`.** The region selects `seq, icon, label, metric_value` from `APX_DEMO_DASH_KPI_V`, but the view defined in `install.sql` exposes `kpi_1, kpi_2, kpi_3`. Either the installed view differs from the script, or the page is broken. Resolve this through the Oracle Dictionary (WP9.3b) before redesigning the dashboard. This is the only DEP-012 failure.
2. **SCH005: identity `ON NULL`.** In PostgreSQL, an explicit `NULL` ID fails instead of generating a value. NestJS writers must omit identity columns. Confirmed by test.
3. **SCH003: `DATE` → `timestamp(0) without time zone`, `SYSDATE` → `LOCALTIMESTAMP(0)`.** Confirm the single clock/timezone policy (Asia/Jakarta server time vs UTC instants). The engineering standard prefers `timestamptz` for instants (`requested_on`, `acted_on`, audit `*_on`).
4. **SCH002: unconstrained `NUMBER` → `numeric`** (amounts, qty, `level2_limit`, `doc_id`, `last_no`). Confirm the precision/scale with data profiling, or keep `numeric`.
5. **SCH004: character columns.** Oracle stores `''` as NULL. Decide whether NOT NULL text columns also need `CHECK (col <> '')` or service-side normalization.
6. **SCH009: `LINE_AMOUNT` stored, not virtual.** It is computed on write. Loaders must exclude it (see `loadPlan`).
7. **EXP005: `||` in display views.** `request_lines_v.request_id_dsp` becomes NULL when `request_no` is NULL. Oracle would render `' - purpose'`. Decide whether to use `concat_ws`/`COALESCE`.

## 7. Trigger behavior inventory (input for WP9.4)

The five triggers are inventoried in [report §6](wp9.3/f170134/schema-conversion-report.md). In summary:
- Audit stamps (`created_*`/`updated_*`) are set from `APX_DEMO_SEC_PKG.APP_USER` and `SYSDATE` on all five triggers.
- Upper-case normalization is applied to username, role, department, item and UOM codes.
- `REQUESTS_TRG`:
  - forces `status := 'DRAFT'` on insert and derives `request_no` via `APX_DEMO_DOC_PKG.NEXT_NO('REQ')`;
  - guards status transitions with errors -20110, -20111 and -20112;
  - locks `department_id`, `purpose` and `need_date` after submission;
  - reads the package bypass flag.
- `REQUEST_LINES_TRG` reads the parent status, raises -20121, and handles ORA-04091 during cascade delete.

DEP-006 confirms that every `:NEW`/`:OLD` column exists and that no trigger writes the generated column. DEP-007 confirms that every called package member is declared in its spec. All triggers are MANUAL. None is emitted to PostgreSQL.
