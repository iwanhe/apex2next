## 3. Schema conversion assessment

Six tables have `GENERATED BY DEFAULT ON NULL AS IDENTITY` columns: USER_ROLES, APPROVALS, DEPARTMENTS, ITEMS, REQUESTS and REQUEST_LINES. REQUEST_LINES also has virtual generated column `LINE_AMOUNT = QTY * UNIT_PRICE`. The current WP8.1 converter intentionally blocks identity/generated-column tables.

Only three tables are included in the partial DDL draft:
- `APX_DEMO_ROLES`
- `APX_DEMO_DOC_TYPES`
- `APX_DEMO_DOC_SEQ`

The draft is not a complete application schema or approved deployment migration. The six other tables remain blocked pending identity/virtual-column decisions. All 8 CHECK predicates need explicit preservation; the current converter reports CHECK constraints for review and does not emit them. The 3 post-create FKs, 4 explicit indexes, views, triggers, PL/SQL, grants and seed DML are not included in the partial DDL.

Other conversion decisions: Oracle DATE includes time-of-day and needs a target date/timestamp policy; NUMBER precision/scale must be verified; VARCHAR2 BYTE/CHAR semantics and Oracle empty-string behavior need review; DEFAULT SYSDATE needs explicit timezone/clock semantics; FORCE VIEW has no direct PostgreSQL equivalent; DUAL and NVL require query rewrites. There is no standalone CREATE SEQUENCE; document numbering uses DOC_SEQ table.

See [conversion dispositions](wp9.2-conversion-disposition-f170134.md) and [partial PostgreSQL DDL](wp9.2-postgresql-ddl-draft.sql).

| Triggers | Audit stamps, normalization, status/field guards, parent-child edit rules | Explicit domain invariants/service write path; narrow DB triggers only if justified |

Detected in APPROVAL_PKG: 4 EXECUTE IMMEDIATE statements, 10 DBMS_ASSERT occurrences, 6 RAISE_APPLICATION_ERROR occurrences, one WHEN OTHERS handler, and two FOR UPDATE queries. These are lexical counts, not parser-certified semantics.

### High-priority review findings

1. **SEC-001 — fail-open bootstrap:** SEC_PKG returns true for all role checks while no ADMIN assignment exists. This must not be carried into target authorization. Replace with an explicit, time-bounded bootstrap enrollment and deny-by-default behavior.
2. **SEC-002 — bypass state:** APPROVAL_PKG exposes SET_BYPASS and package-global bypass state used by triggers. Verify grants/call paths; never expose a client-controlled bypass in the target.
3. **CONC-001 — submit race:** SUBMIT reads document status without locking the document row before status update and approval insertion. Concurrent submits may create duplicate pending approvals. Lock the document and add idempotency/uniqueness invariants.
4. **CONC-002 — numbering race:** DOC_PKG MERGE-creates a period row then increments it. Test simultaneous first use and retries; target should use one atomic upsert/update-returning operation.
5. **DYN-001 — configurable dynamic SQL:** four dynamic execution sites use configured identifiers and/or AMOUNT_EXPR/VALIDATE_PROC. DBMS_ASSERT identifier checks do not validate arbitrary SQL expression semantics. Review config write access and prefer a closed handler registry.
6. **TX-001 — transaction ownership:** packages do not COMMIT; callers own transactions. Define atomicity for request status, approval rows, second-level approval and rollback on every intermediate failure.
7. **AUTH-001 — APEX identity:** SYS_CONTEXT('APEX$SESSION','APP_USER') has no direct PostgreSQL equivalent. Use a trusted server-side authenticated principal context.
8. **TRG-001 — trigger parity:** test status transitions, immutable fields, audit stamps, line edit guards and parent cascade deletion. The ORA-04091 exception pattern is Oracle-specific and must be redesigned.
